# coin-breaker: test results

A Chainlink CRE workflow that watches Witching Hour's Zora coins on Base and pauses
automated buying when a pool behaves abnormally.

- **Trigger:** cron, every 5 minutes
- **Coins:** every creator and content coin of witchinghour, mirrorizm, phletch, phunkii and
  ilikeitifyoudo, plus witchinghourmusic (64 on 2026-10-06), generated by `scripts/sync-coins.ts`
- **Reads:** each pool's price and in-range liquidity at the finalized block, compared with 1800
  blocks (~1 hour) earlier, straight from the Uniswap v4 PoolManager
  `0x498581fF718922c3f8e6A244956aF099B2652b2b` with `extsload` (60 coins per read). CRE allows 15
  EVM reads per execution; 64 coins use 6 (1 header + 2×2 extsload + 1 pause check), and
  `MAX_COINS = 120` is the most that fits.
- **Trips on:** ≥15% price drop, ≥30% spike, ≥50% liquidity drop, or zero liquidity
  (about 3× the worst hourly move in 39 days of history: −5.1% / +9%)
- **Writes:** a signed CRE report, only for tripped coins not already paused (checked through
  Multicall3, at most 25 per report), to `CoinCircuitBreaker` on Base
  (`0xBFeDCca4dE6cF908C1cf375D430DaDDc15C9bdca`, forwarder `0xF8344CFd5c43616a4366C34E3EEE75af79a74482`)
- **Consumer:** the whm-flywheel accumulator checks `isPaused(coin)` before every buy (fails closed)

## 5. All 64 coins, live Base mainnet, read-only (2026-10-06)
The workflow's read path and `decide()` run with viem against live Base (the CRE CLI couldn't be
installed in that environment):
```
blocks 52249119 vs 52247319; 64 coins: { OK: 60, NO_LIQUIDITY: 4 }
TRIP fuxkaround / Powpow / Suppy / Poo: NO_LIQUIDITY   (dead pools: paused once, then skipped)
isPaused: all false
EVM reads used: 6; largest request 3908 bytes (limit 5 KB); worst-case multicall 3652 bytes
```
`extsload` values for the witchinghour pool matched StateView `getSlot0` / `getLiquidity` exactly.
The production forwarder `0xF8344CFd5c43616a4366C34E3EEE75af79a74482` matches the Base mainnet
KeystoneForwarder in Chainlink's forwarder directory, and is what the deployed breaker trusts.

Changes that came with covering every coin:
- Price change is computed exactly from the two sqrtPrices. The old 1e18-scaled price rounds to
  0 for cheap coins in 6-decimal USDC pools (8 of ours), which would have failed the whole run.
- A pool created inside the lookback window is `NEW` (skipped) instead of failing the run.
- Coins already paused aren't re-reported, so a dead pool doesn't cost a transaction every 5 min.
- `gasLimit` 2,500,000 (25 pauses × ~70k gas, under the 10M CRE per-transaction quota).

## Deploy (run these yourself; needs CRE Early Access and your linked key)
```
cd cre-project/coin-breaker
cre login && cre whoami
cre account access                                       # Early Access must be granted
cre account link-key --target production-settings        # the key that will own the workflow
cre workflow simulate coin-breaker --target local-simulation --non-interactive --trigger-index 0
cre workflow deploy coin-breaker --target production-settings     # registers it, paused
cre workflow activate coin-breaker --target production-settings   # starts the 5-minute cron
```
Then restrict the breaker to this workflow, so no other CRE workflow can pause your coins
(owner-only; the owner is `0x0f8a…4817`, the wallet that deployed it):
```
cast send 0xBFeDCca4dE6cF908C1cf375D430DaDDc15C9bdca 'setExpectedAuthor(address)' <linked workflow owner> \
  --rpc-url https://base.drpc.org --interactive
```
New posts: `cd coin-breaker && bun run sync-coins:check`; if out of date, `bun run sync-coins`,
simulate, then `cre workflow update coin-breaker --target production-settings`.
Unpause a coin (owner): `cast send 0xBFeD…bdca 'unpause(address)' <coin> --rpc-url https://base.drpc.org --interactive`.

## Tests
- Workflow: 24 unit tests (pool id, extsload slots and decoders, exact price change both sides incl.
  a USDC pool where the scaled price rounds to 0, NEW/UNINITIALIZED pools, thresholds at the
  boundaries, read and request-size quotas, synced configs, config fail-closed)
- Flywheel: 13 tests incl. "paused coins are never quoted or bought" and "a failed breaker read fails closed"

## Found along the way (template feedback for Chainlink)
- `bring-your-own-data-ts` NAV: `api.m0.xyz` no longer resolves. Chainlink's own M0 external adapter
  already uses `https://mnav.m0.xyz/api/rpc`.
- Same workflow computes NAV with JS floats (`3208070.0437240005`); it should use scaled integers.
- `prediction-market-ts` dispute workflow reads at the finalized block, so a fresh DisputeRaised needs 64+
  blocks before the status reads as Disputed (worth a README note).
